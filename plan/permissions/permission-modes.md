# Permission modes inside bi — implementation plan

A mode answers one question: **what may bi do without stopping to ask me?** For example, use Plan to investigate a bug without changing the code. When you're ready to make the fix, switch to Edits. Switching modes changes the rules for the **next tool call**; it doesn't undo a change or stop a command already running.

This is a feature of the existing bi extension, not a second extension. Loading bi with `pi -e ./` should be enough. Keep `package.json` pointing at `./src/index.ts`; don't create a `.pi/extensions/permission-modes/` copy, a second manifest, or new dependencies.

## What the user sees

- The existing interactive footer starts with a short text badge, e.g. **`Mode: Plan`**. It sits alongside the model, project/Git and usage information. You shouldn't have to infer permissions from a color or open a menu to check them.
- Press **Alt+M** to cycle **Manual → Edits → Plan → Auto → Manual**. The installed Pi keybindings document assigns Shift+Tab to thinking level; leave that alone. Show Alt+M in bi's key hints.
- Do not register a permission-mode slash command. Use the same transition function for the shortcut, plan approval and restore so the footer never advertises a different policy from the one being enforced.

| Footer label | Mode name | In simple terms |
|---|---|---|
| Manual | `default` | Ordinary reads don't need a mode prompt. Ask before changing a file or running an unclassified command. |
| Edits | `acceptEdits` | Also permit ordinary edits in this project and narrowly verified local file operations. Ask about outside paths or uncertain commands. |
| Plan | `plan` | Investigate without changing project files. Only the current session's designated plan note may be written. |
| Auto | `auto` | Start with Edits. An optional reviewer can assess eligible uncertain calls; if unsure or unavailable, ask the user. |
| No prompts | `dontAsk` | When a call needs approval, decline rather than interrupt. Only select at launch with `--permission-mode dontAsk`. |
| Bypass | `bypassPermissions` | Skip routine **mode** prompts, not bi's existing safety checks. Require `--permission-mode bypassPermissions` and interactive confirmation; otherwise refuse. |

Keep the last two out of the shortcut cycle. An `allow` in this table means *pass the mode gate*, not *skip the underlying tool's approval*. For example, bi may still ask before running a shell command in Edits. No prompts mode must decline at both gates if either would require a dialog.

## Build it in this repository

1. **Wire one session-aware controller.** Create `src/extension/permission-modes/` for mode definitions, policy and Pi event wiring. Register it once from `src/index.ts`; pass the controller to the existing tool adapter and TUI rather than storing a process-wide current mode. Register Alt+M with `pi.registerShortcut`. Check signatures and key conflicts against the installed `@earendil-works/pi-coding-agent` types/docs before implementation. Compose the current-mode instruction with `src/extension/system-instruction.ts`; it describes the policy, it does not enforce it.

2. **Decide before tools execute.** Keep the decision function independent of Pi: given mode, tool name, arguments, working directory and rules, return `allow`, `ask` or `deny` with a short reason. Gate agent tool calls with Pi's `tool_call` hook (including tools registered outside bi). Inventory `createToolSystem()` and separately registered tools such as `goal_report`: distinguish reading, writing, execution, delegation and session bookkeeping by what they actually do. Inspect *every* path in `apply_patch`, `copy` and `move`; do not treat `terminal` input, `background`, `run_code`, `subagent` or Git mutations as reads. Unknown tools/invalid arguments never silently pass. Preserve `src/extension/register-tools.ts` → dispatcher validation, cancellation, file tracking and per-call command/destructive checks. In No prompts or noninteractive modes, a required confirmation returns false, not yes. Don't install a blanket `allowCommand` callback.

3. **Keep the safety rules small and testable.** First apply hard blocks, then Plan's write boundary, then deny → ask → allow rules, then mode defaults. Neither a saved approval nor Auto can override an explicit ask/deny or grant unknown capabilities. Ask means allow once, allow this exact normalized call for this session, or deny; dismissal, missing UI or UI errors mean deny. Never save a wildcard approval for shell input.

   - Resolve paths against `ctx.cwd`, following real paths (nearest existing parent for new files). Check path components, symlinks and both ends of multi-path operations. Ask about sensitive reads; block writes to credentials (`.env*`, keys, SSH), Git internals, `node_modules`, Pi settings/extensions and shell startup files in every mode.
   - Only recognize simple shell forms whose command, options **and operands** are understood. A quoted semicolon in `grep ';' a.txt` is data; chaining, redirects, substitutions, leading assignments, script execution and mutating `find` flags aren't read-only. Check shell file operands against the same path rules. Block recognized critical operations such as recursive root/home deletion, device writes, `sudo`, remote scripts piped to a shell and force pushes even in Bypass. Parsing failure is not permission. This is a tool-call filter, **not an OS sandbox**.
   - Keep trusted user rules in optional `~/.pi/agent/permission-modes.json`; optional `.pi/permission-modes.json` may only add asks/denials. Do not let a cloned repository grant permissions, change the startup mode or enable Auto review. Leave bi's safe `.pi/config.json` preferences separate. Validate config and report invalid rules rather than broadening access.

4. **Show the live mode in the real footer.** Extend `installTui` in `src/tui/index.ts` with a mode reader/change subscription. Add the badge to the existing `parts` array with the highest `fitJoin` retention priority: drop tokens/cost and then other fields before dropping the mode. Use plain text in ASCII mode and a short label on narrow terminals. Call `tui.requestRender()` on change (don't wait for the five-second Git timer); unsubscribe in the footer's existing `dispose()`. Don't install another footer or rely on `setStatus` being rendered. Add the shortcut to the existing `src/config/bi.config.json` hints. No footer or keyboard setup is needed in print mode.

5. **Restore only valid choices.** Model persistence on `src/commands/goal/state.ts`: append a namespaced mode entry and read the current session branch on start/resume/branch change. Resolve launch flag → valid restored mode → trusted user default → Manual. Recheck restricted-mode launch conditions on every entry path; a transcript cannot unlock Bypass. Clear temporary approvals on session change and reload. Restore state before first footer render or goal continuation.

6. **Finish Plan and Auto.** In Plan, expose read-only tools and a narrowly scoped plan-note writer targeting `.pi/plans/<session-id>.md` under the verified project root. Hide ordinary mutation/execution/delegation tools; still deny them in the hook. The dedicated writer validates its destination immediately before writing. Preserve the prior active tool list on exit. When the note changes, offer **start in Edits**, **start in Manual**, **keep planning**, or **discard the note**. Only explicit approval starts implementation; never auto-approve on goal continuation or without UI. In Auto, use an injectable reviewer only for eligible mode-default asks. Send no file contents, secrets or tool output; omit review if inputs can't safely be summarized. Require a validated decision and timeout (15 seconds); failure falls back to asking. After three declines in a turn or twenty in a session, switch to Manual and update the badge. If there's no suitable configured model API, ship the documented static fallback rather than adding a network client.

## How we'll know it works

- **Policy tests** (`tests/permissions/permission-modes.test.ts`): table-test all six modes. Include inside/outside edits, symlink and multi-file escapes, protected writes in Bypass, read-only vs chained shell, unknown tools, project allow-rule rejection, exact session approvals, no-UI refusal and reviewer timeout. Test Plan note writes against the *specific session path*, not just its directory.
- **Integration tests** under `tests/`: exercise the shortcut through all four cycle steps and wraparound, restricted-mode refusal, branch restore, immediate footer redraw/disposal, narrow ASCII output, and existing command/destructive callbacks still refusing. Exercise the Plan approval path alongside `/goal` without scheduling a second kickoff. Run `npm test` and `npm run typecheck` at each implementation milestone.
- **Manual acceptance**: start `pi -e ./` in a scratch project. Check `Mode: Manual` before the first prompt. Press Alt+M twice: the footer should immediately read `Mode: Plan`; try an edit and verify the file stays unchanged. Press Alt+M three more times to reach Edits, resize the terminal, and resume the session: the badge and the next tool decision must agree each time. Confirm `/model` still opens the model selector, Shift+Tab still changes thinking level, `/reload` doesn't duplicate handlers, and a print-mode call needing approval fails without hanging.
- **Document in `README.md`** the mode table, shortcut, launch-only modes, trusted config, and what the mode gate cannot guarantee. No separate installation instructions should be needed.
